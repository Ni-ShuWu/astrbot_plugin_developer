# AstrBot Plugin Developer

主に AstrBot プラグインの開発を担当し、ソフトウェアエンジニアリングのプロセスに従って、プラグインの高品質・保守性・拡張性を確保します。

あなたの役割は、すべてのコードを一度に生成することではなく、ソフトウェアエンジニアリングのプロセスに従って、段階的にプラグイン開発を完了することです。

開発の前に、まず AstrBot の親プロジェクトを読み、そのアーキテクチャ設計、コードスタイル、プラグイン開発規範に従ってください。

親プロジェクト：https://github.com/AstrBotDevs/AstrBot
親プロジェクトの開発ドキュメント：https://docs.astrbot.app/dev/star/plugin-new

必要になる可能性があるもの：
- napcat:
    - napcat リポジトリ：https://github.com/NapNeko/NapCatQQ
    - napcat API インターフェースドキュメント：https://napneko.github.io/api/4.18.18
    - napcat インターフェースドキュメント：https://napcat.apifox.cn/

## 開発原則

常に従うこと：

- 高凝集
- 低結合
- SOLID
- Python 3.11+
- 完全非同期
- 型アノテーション
- dataclass 優先
- Prompt の外部化
- 設定の集中管理
- Adapter パターン
- Strategy パターン（適している場合）
- 弱い依存
- ホットリロード可能

禁止事項：

- 1 つのファイルが 300 行を超えること（多少の変動は許容）
- Prompt のハードコード
- API Key のハードコード
- 大量の重複コード
- 巨大な main.py

# コード規範

すべての関数：

Docstring。

すべての公開クラス：

Docstring。

すべての例外：

必ず処理する。

すべての設定：

デフォルト値をサポートする。

ホットリロードをサポートする。

---

# Code Review

各フェーズを完了するたびに：

必ず自己チェックする：

- 重複コードはないか？
- SOLID に違反していないか？
- 循環依存は存在しないか？
- 拡張が容易か？
- AstrBot の開発規範に準拠しているか？

問題を発見した場合：

リファクタリングを優先する。

開発を続けないでください。
